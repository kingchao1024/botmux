# 变更规划与授权

## 事实

- 当前请求是本次允许文件、禁止动作和验收条件的真源。
- [docs/plans/](../plans/) 与 [docs/plan/](../plan/) 仅提供背景，不会扩大新请求的授权范围。

## 必须先写清的内容

实现前写明目标、范围文件/行为、验收证据和禁止项。实现与独立验收必须分离：实现者交付 diff 和自测证据，独立验收者不能把作者断言当结论。

## 建议

- 采用满足验收条件的最小可逆改动；没有现实需要时，不新增依赖、配置、抽象或无关重构。
- 检查失败时如实报告证据，不得报完成；需要扩大范围时先取得决定。
- commit、push、merge、release、delete 和生产动作均需单独明确授权，即使代码和本地检查已通过。
